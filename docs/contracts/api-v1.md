# REST API: новые и изменённые методы

**Статус:** черновик на согласование, 18.10.2026. Готовит Котко (черновик подготовил Халилов), согласует Халилов. Это описание до появления OpenAPI, который будет генерироваться из кода (план Котко, К7). При расхождении с кодом после реализации верен OpenAPI.

Что уже реализовано, отмечено в заголовке раздела. Остальное — договорённость, по которой интерфейс можно делать на подменённых ответах.

## 1. Общие правила

| Что | Как |
|---|---|
| Базовый адрес | `/api/v1` |
| Авторизация | заголовок `Authorization` с данными запуска мини-приложения Telegram, как сейчас. Без него — `401`. С 23.10.2026 данные старше суток не принимаются (`401`, `INIT_DATA_EXPIRED`): интерфейс просит закрыть и открыть приложение заново |
| Формат | JSON в UTF-8, имена полей в `snake_case`; даты — ISO 8601 |
| Ошибка | объект с полями `code` (код из таблицы ниже), `message` (текст для человека), `field` (имя поля, если ошибка в нём), `trace_id`. Интерфейс выбирает поведение по `code`, а не по тексту |
| Чужие Telegram ID | ни один метод не отдаёт Telegram ID других пользователей. Свой — можно, в `GET /me` |

**Коды ошибок:**

| Код | HTTP | Когда |
|---|---|---|
| `UNAUTHORIZED` | 401 | нет данных запуска или подпись неверна |
| `INIT_DATA_EXPIRED` | 401 | данные запуска старше суток или из будущего (план Жерко, Ж5, пункт 3) |
| `FORBIDDEN` | 403 | не та роль или чужая работа |
| `ADMIN_ACCOUNT` | 403 | регистрация с аккаунта администратора: его роль меняется только в базе (решение 11) |
| `NOT_FOUND` | 404 | работа или файл не найдены |
| `VALIDATION_ERROR` | 400 | поле не прошло проверку; в `field` — какое |
| `GROUP_NOT_FOUND` | 400 | группы нет в справочнике ИИС |
| `IIS_UNAVAILABLE` | 503 | ИИС недоступна, и в справочнике в базе нужных данных нет |
| `EMAIL_DOMAIN_NOT_ALLOWED` | 400 | почта преподавателя не `@bsuir.by` |
| `EMAIL_TAKEN` | 409 | почта уже зарегистрирована |
| `EMAIL_NOT_IN_IIS` | 400 | почты нет среди сотрудников ИИС |
| `CODE_INVALID` | 400 | код подтверждения неверный или просрочен |
| `NOT_A_PDF` | 400 | файл не PDF |
| `FILE_TOO_LARGE` | 413 | файл больше предела |
| `VERDICT_ALREADY_SET` | 409 | по работе уже вынесен вердикт |
| `COMMENT_REQUIRED` | 400 | на доработку без текста и без единой аннотации |
| `RATE_LIMITED` | 429 | слишком частые запросы |

**Кода `STUDENT_CARD_TAKEN` нет.** Номер студенческого не запрашивается и не хранится (решение 4 в редакции 18.10.2026), поэтому и «занятого номера» не бывает. Совпадение ФИО регистрацию не блокирует и кода ошибки не даёт: студент просто получает номер тёзки (раздел 2).

## 2. Студент в ответах

Везде, где в ответе есть студент, он передаётся одним и тем же объектом `student`. В списках преподавателя он заменит нынешнее строковое поле `student_name` (на переходный период отдаются оба).

| Поле | Тип | Что значит |
|---|---|---|
| `last_name` | строка | фамилия |
| `first_name` | строка или `null` | имя; `null` у старых аккаунтов, где известны только инициалы |
| `middle_name` | строка или `null` | отчество, если есть |
| `full_name` | строка | готовая строка для показа: «Иванов Иван Иванович», у старых аккаунтов — как было введено |
| `group` | строка | номер группы, 6 цифр |
| `has_namesake` | логическое | в той же группе есть студент с таким же ФИО |
| `namesake_number` | число или `null` | только при `has_namesake = true`: постоянный номер тёзки в группе, начиная с 1 |

Тёзки — студенты одной группы, у которых после нормализации совпадают фамилия, имя и отчество. Нормализация: регистр не учитывается, «ё» = «е», лишние пробелы убираются, дефисы не учитываются.

Номер выдаётся при регистрации — на единицу больше наибольшего среди тёзок — и потом не меняется, даже если кто-то из тёзок удалит аккаунт. Поэтому номера могут идти с пропусками: (1) и (3). Интерфейс показывает номер как есть и не перенумеровывает.

Как показывать (решение 4): рядом с именем номер в скобках и значок «тёзка» — «Иванов Иван Иванович (2)». У значка — текстовая подпись для программ чтения с экрана. Цветом не помечать, Telegram ID ни целиком, ни частью не показывать.

## 3. `GET /groups` — подсказки групп

Вызывается до регистрации: пользователь уже подтверждён подписью Telegram, но роли у него ещё нет.

| Параметр | Обязательный | Что значит |
|---|---|---|
| `q` | да | начало номера группы: от 2 до 6 цифр |
| `limit` | нет | сколько вариантов вернуть: от 1 до 20, по умолчанию 10 |

Ответ — массив групп, номера которых начинаются с `q`, по возрастанию номера:

| Поле | Тип | Пример | Откуда в ИИС |
|---|---|---|---|
| `number` | строка | 321702 | `name` |
| `speciality` | строка | сокращение специальности | `specialityAbbrev` |
| `speciality_name` | строка | полное название специальности | `specialityName` |
| `faculty` | строка | сокращение факультета | `facultyAbbrev` |
| `course` | число | 4 | `course` |

| Ситуация | Ответ |
|---|---|
| совпадений нет | `200`, пустой массив. Если введено 6 цифр — интерфейс сразу пишет «Такой группы нет в ИИС» |
| `q` не из цифр или короче 2 символов | `400`, `VALIDATION_ERROR`, `field = q` |
| частые запросы | `429`, `RATE_LIMITED`; предел — предложить Жерко, например 30 запросов в минуту на пользователя |
| ИИС недоступна | ответ как обычно: поиск идёт по справочнику в базе (`iis_groups`), который обновляется раз в сутки и при старте |
| справочник ещё ни разу не загружен и ИИС недоступна | `503`, `IIS_UNAVAILABLE`; поле группы в форме работает как обычное |

Размер справочника (замер 18.10.2026): в ИИС 426 групп; список только из номера, сокращения специальности и курса — около 29 КБ. Поэтому возможен и вариант без параметра `q`: метод отдаёт весь список, а интерфейс фильтрует сам. Какой вариант брать — решает интерфейс.

## 4. `POST /register` — изменённая регистрация

**Студент** вместо одного поля `full_name` в формате «Иванов И.И. (гр. 321702)» передаёт ФИО и группу по отдельности:

| Поле | Обязательное | Проверка |
|---|---|---|
| `role` | да | `STUDENT` |
| `last_name` | да | 1–100 символов: буквы кириллицы, дефис, пробел |
| `first_name` | да | то же |
| `middle_name` | нет | то же; нет отчества — поле не передаётся или `null` |
| `group` | да | 6 цифр; группа должна быть в справочнике |

Сервер обрезает пробелы по краям, схлопывает повторные пробелы и ставит заглавную букву в начале каждой части имени, в том числе после дефиса. Номера студенческого в запросе нет. Старое поле `full_name` принимается, пока интерфейс не перейдёт на новую форму.

**Преподаватель** — без изменений: `role = TEACHER`, `email`, `code`. ФИО берётся из ИИС.

**Администратор** регистрацией не создаётся: `role = ADMIN` даёт `400`, а регистрация с аккаунта, у которого в базе роль `ADMIN`, — `403`, `ADMIN_ACCOUNT` (сделано 23.10.2026, решение 11). Роль записывают в базу вручную — README, «Администратор».

**Ответ `200`:** `status = OK`, `role` и `user` — свои данные в том же виде, что в `GET /me` (раздел 5).

| Ошибка | Код | HTTP |
|---|---|---|
| поле не заполнено или не прошло проверку | `VALIDATION_ERROR`, в `field` — имя поля | 400 |
| группы нет в справочнике | `GROUP_NOT_FOUND` | 400 |
| справочник пуст и ИИС недоступна | `IIS_UNAVAILABLE` | 503 |
| почта не `@bsuir.by` | `EMAIL_DOMAIN_NOT_ALLOWED` | 400 |
| почта уже зарегистрирована | `EMAIL_TAKEN` | 409 |
| почты нет в ИИС | `EMAIL_NOT_IN_IIS` | 400 |
| неверный или просроченный код | `CODE_INVALID` | 400 |

## 5. `GET /me` — изменено, **частично сделано 21.10.2026**

Сделано: `telegram_id`, `role`, `full_name`, `last_name`, `first_name`, `middle_name`, у студента — `group`; интерфейс показывает в настройках «Фамилия И. О.» и группу. `namesake_number` и `profile_incomplete` — вместе с регистрацией по полям (К2).

| Поле | Тип | Что значит |
|---|---|---|
| `telegram_id` | число | свой Telegram ID, как сейчас |
| `role` | строка | `STUDENT`, `TEACHER`, `ADMIN` или `NONE` |
| `last_name`, `first_name`, `middle_name`, `full_name`, `group` | как в разделе 2 | свои данные; `group` — только у студента |
| `course`, `semester` | число или `null` | только у студента, **сделано 23.10.2026** (решение 11): курс и семестр, которые сервер определил по группе и дате с учётом исправлений администратора. `null` — не определились: проверятся только оформление и согласованность текста |
| `stage` | число или `null` | только у студента: к какой опроцентовке проверяется работа — ближайшая не прошедшая по датам администратора для курса студента; `null` — итоговая сдача или даты не заданы |
| `deadline` | строка или `null` | только у студента, **сделано 24.10.2026**: срок сдачи работы его курса, `ГГГГ-ММ-ДД`; `null` — не задан |
| `course_overridden` | логическое | курс задан администратором, а не определён по номеру группы |
| `cloud_check` | логическое | только у студента, **26.10.2026** (решение 13): работы сейчас проверяет облачная модель, выбранная администратором, — экран сдачи говорит об этом и о том, что персональные данные убираются |
| `namesake_number` | число или `null` | только у студента, у которого есть тёзка: свой номер для раздела «Мои данные» («Среди студентов группы с таким же ФИО вы — №2»). Без тёзки — `null`, и раздел номер не показывает. Данных другого студента ответ не содержит |
| `profile_incomplete` | логическое | `true`, если у студента нет имени — аккаунт по старой форме. Интерфейс предлагает дополнить ФИО |

Исправление ФИО и группы — отдельный метод `PATCH /me` с полями как в регистрации студента (план Котко, К2).

## 6. Списки преподавателя — изменено

`GET /teacher/submissions` и `GET /teacher/history`: у каждой работы добавляется объект `student` из раздела 2. Поле `student_name` остаётся на переходный период.

**Сделано 21.10.2026 (решение 9):** очередь `GET /teacher/submissions` содержит и отклонённые по оформлению работы (`status: REJECTED`), а из версий одной работы — только последнюю. Новые поля:

| Поле | Тип | Что значит |
|---|---|---|
| `content_status` | строка или `null` | **с 23.10.2026**: как идёт содержательная проверка — раздел 13. Отклонённая работа появляется в очереди сразу после проверки оформления, и `PENDING` значит «содержание ещё проверяется» |
| `version` | число | номер версии работы, с 1 |
| `first_submitted_at` | строка | когда пришла первая версия — по ней засчитывается срок сдачи; у первой версии равна `created_at` |
| `has_review_file` | логическое | преподаватель уже приложил PDF с пометками (раздел 8) |
| `review_annotations` | число | сколько комментариев в нём прочитано |

В истории — `has_review_file` и `review_annotations`. В списке студента `GET /submissions` — те же два поля, но заполнены только после вердикта: до него преподаватель может заменить файл.

PDF-отчёт проверки `GET /submissions/{id}/report` отдаётся автору работы и её преподавателю; без подписи и чужим — `403`.

Работа для преподавателя `GET /teacher/submissions/{id}/pdf` скачивается под именем по форме — `КР7_321702_Терешкова.pdf` (решение 10), если известны вид работы, семестр, группа и фамилия; иначе — под исходным именем.

## 7. `POST /upload` — изменено, **сделано 18.10.2026, профиль — 23.10.2026, вид работы — 26.10.2026**

Поля — `file` и `teacher_id`. **Вид работы студент не передаёт** с 26.10.2026 (решение 11, правка): в 8 семестре сервер сразу ставит `diploma`, в остальных вид станет известен из титульного листа — обработчик присылает его в отчёте (`document.title_page.work_type`), и бэкенд записывает его в работу. Поле `work_type` от клиента пропускается. Задание уходит с моделью, которую выбрал администратор (раздел 16).

**Семестр и этап студент не передаёт** (решение 11, 23.10.2026): сервер определяет семестр по группе студента и дате, этап — по датам опроцентовок, с учётом исправлений администратора, и кладёт их в задание обработчику. Поля `semester` и `stage` от клиента не принимаются — пропускаются. Что определилось, интерфейс показывает из `GET /me` (раздел 5).

Новая работа получает статус `QUEUED`; дальше — раздел 13.

Файл сохраняется под сгенерированным именем, исходное имя хранится в базе и по-прежнему приходит в поле `file_name` в списках работ. Ответ не изменился. С 21.10.2026 интерфейс передаёт профиль (выбор на экране загрузки), предел размера — 50 МБ и в Docker. Загрузка тому же преподавателю связывается с предыдущей работой как новая версия (решение 9). Сейчас ошибки здесь ещё в старом формате (`error` с текстом), коды из раздела 1 появятся с общим обработчиком ошибок. Приём DOCX (решение 3) — следующий шаг: появится, когда будет конвертер.

## 8. `POST /teacher/submissions/{id}/review-file` — размеченный файл, **сделано 21.10.2026**

Преподаватель загружает PDF, в котором оставил комментарии, и сразу видит, что система прочитала. Разбор — `review/AnnotationExtractor` (PDFBox): тот ли документ, решается по числу страниц и доле общих слов первых трёх страниц (не меньше 60 %). Ошибки этого и следующих методов — объект с полями `code`, `error`, `message`; `trace_id` появится с общим обработчиком ошибок (К7).

| Что | Как |
|---|---|
| Запрос | `multipart/form-data`, поле `file` — PDF |
| Предел размера | 50 МБ, как у загрузки работ. Через бота файлы скачиваются только до 20 МБ — пределы выровнять |
| Кто может | преподаватель этой работы, пока вердикт не вынесен |
| Повторная загрузка | заменяет предыдущий размеченный файл этой работы |

**Ответ `200`:**

| Поле | Тип | Что значит |
|---|---|---|
| `review_file_id` | число | идентификатор загруженного файла; передаётся в вердикт |
| `annotations` | массив | извлечённые комментарии, объекты из раздела 10 |
| `warnings` | массив | предупреждения: объекты с полями `code` и `message` |

| Предупреждение | Когда | Что показать |
|---|---|---|
| `NO_ANNOTATIONS` | комментариев не найдено | «Комментариев не найдено — возможно, файл сохранён через печать в PDF, и пометки стали частью страницы». Файл всё равно прикладывается, можно написать текстовый комментарий |
| `DIFFERENT_DOCUMENT` | не совпало число страниц или текст страниц | «Похоже, загружен другой файл». Не отказ |

| Ошибка | Код | HTTP |
|---|---|---|
| не PDF | `NOT_A_PDF` | 400 |
| больше предела | `FILE_TOO_LARGE` | 413 |
| не своя работа | `FORBIDDEN` | 403 |
| работы нет | `NOT_FOUND` | 404 |
| вердикт уже вынесен | `VERDICT_ALREADY_SET` | 409 |

## 9. `POST /teacher/submissions/{id}/verdict` — изменено, **сделано 21.10.2026**

Вердикт можно вынести и по отклонённой работе (решение 9). Повторный вердикт — `409`, `VERDICT_ALREADY_SET`.

| Поле | Обязательное | Что значит |
|---|---|---|
| `verdict` | да | `APPROVED` или `REVISION` |
| `comment` | нет | общий комментарий-резюме |
| `review_file_id` | нет | размеченный файл из раздела 8 |

Правило меняется: на доработку можно отправить, если есть **либо** текст комментария, **либо** размеченный файл хотя бы с одной аннотацией. Иначе — `400`, `COMMENT_REQUIRED`.

## 10. `GET /submissions/{id}/annotations` — комментарии преподавателя, **сделано 21.10.2026**

Кто может: преподаватель этой работы — всегда; студент — автор работы — после вердикта (до него файл может быть заменён), иначе `403`.

**Ответ `200`:** `review_file_id` (или `null`, если размеченного файла нет), `uploaded_at`, `warnings` (как при загрузке) и массив `annotations`. Нет размеченного файла — пустой массив, а не ошибка.

| Поле аннотации | Тип | Что значит |
|---|---|---|
| `id` | число | идентификатор |
| `page` | число | номер страницы, с 1 |
| `kind` | строка | `NOTE` (заметка-стикер; сюда же знак вставки Caret), `HIGHLIGHT`, `UNDERLINE`, `STRIKEOUT`, `SQUIGGLY` (выделения), `FREE_TEXT` (надпись на странице), `INK` (рисунок от руки), `STAMP` (штамп), `SHAPE` (прямоугольник, овал, линия, многоугольник — добавлено 21.10.2026). Всплывающие окна, ссылки, поля форм и отметки статуса рецензирования («Принято») пропускаются |
| `author` | строка или `null` | автор, как его записала программа просмотра |
| `created_at` | строка или `null` | дата и время комментария |
| `comment` | строка или `null` | текст комментария |
| `quoted_text` | строка или `null` | текст под выделением; только у выделений |
| `rect` | массив из 4 чисел | прямоугольник на странице: левый нижний и правый верхний углы в пунктах PDF; начало координат — левый нижний угол страницы |
| `reply_to_id` | число или `null` | на какой комментарий это ответ; так собираются цепочки |
| `has_snapshot` | логическое | есть картинка области. У `INK` и `STAMP` текста нет — показывать «пометка на странице N» и картинку, если она есть |

Порядок: по странице, на странице — сверху вниз; ответ идёт сразу после комментария, на который отвечает. Картинка области — `GET /submissions/{id}/annotations/{annotation_id}/snapshot`, PNG, если `has_snapshot = true`. **Картинок пока нет:** `has_snapshot` всегда `false`, метода `snapshot` ещё нет.

## 14. Администратор — **сделано 23.10.2026, правки 24.10.2026** (решение 11)

То, что сервер определяет сам — половина учебного года, сроки по курсам, курсы групп, — администратор видит и исправляет в приложении; там же исправляет ФИО и группу пользователя и назначает новых администраторов. Все методы — только для `role = ADMIN`, иначе `403`, `FORBIDDEN`. Изменения календаря возвращают экран целиком — объект ниже, — чтобы интерфейс сразу показал результат. Изменения пишутся в журнал бэкенда с Telegram ID администратора и сохраняются с `updated_by`.

| Метод | Тело | Что делает |
|---|---|---|
| `GET /admin/calendar` | — | экран |
| `PUT /admin/calendar/half` | `{"half": "AUTUMN" \| "SPRING" \| "AUTO"}` | половина года вручную; `AUTO` — снова по дате. Ручная снимается сама, когда дата её догонит. Учебный год от половины не зависит — только от даты, поэтому курсы групп при смене половины не сдвигаются |
| `PUT /admin/calendar/schedule` | `{"courses": [3], "dates": {"1": "2026-10-01", "2": "2026-10-29", "3": null, "deadline": "2026-12-20"}}` | сроки текущей половины года для перечисленных курсов: три опроцентовки и сдача работы; `null` — дата снята. Каждая дата — внутри половины года (осень — 1 августа – 31 января, весна — 16 января – 31 июля) и позже предыдущей, иначе `400` |
| `PUT /admin/groups/{group}/course` | `{"course": 1..4}` | курс группы на текущий учебный год; через год исправление не действует. Первая цифра номера — из `group_digits`, иначе `400` |
| `DELETE /admin/groups/{group}/course` | — | снова по номеру группы |
| `DELETE /admin/groups/{group}` | — | удаляет группу, добавленную вручную (`manual`): только пустую — с людьми `409`, `GROUP_NOT_EMPTY`; нет среди добавленных в этом учебном году — `404` |
| `GET /admin/groups/{group}/people` | — | люди группы: `{group, students, teachers}`, каждый — `{id, name, group}`; `group` у преподавателя — `null` |
| `PUT /admin/users/{id}` | `{"name": "Терешкова Анна Викторовна", "group": "321701"}` | исправляет ФИО и группу **студента** (первая цифра — из `group_digits`). Ответ — экран и `people` прежней группы. Данные преподавателя администратор только просматривает: `409`, `NOT_A_STUDENT` |
| `POST /admin/users/{id}/admin` | — | студента — в администраторы: его работы, размеченные файлы и учебные данные (группа, почта) удаляются, имя остаётся. Ответ — экран. Не студент или сам себя — `409`, `NOT_A_STUDENT` |

`id` — Telegram ID: ключ для изменений, интерфейс его не показывает. Первого администратора вписывают в базу (README, «Администратор»), остальных назначают на экране.

**Экран:**

| Поле | Что значит |
|---|---|
| `today` | сегодня по Минску |
| `academic_year`, `academic_year_title` | учебный год — год начала (`2026`) и подпись (`2026/2027`) |
| `half`, `half_by_date`, `half_overridden` | половина года (`AUTUMN`, `SPRING`) — действующая и по дате; задана ли вручную |
| `max_course` | 4 — в БГУИР курсов не больше четырёх |
| `group_digits` | возможные первые цифры номера группы в этом учебном году: в 2026/2027 — `[3, 4, 5, 6]`, в 2027/2028 — `[4, 5, 6, 7]` |
| `date_window` | `{from, to}` — границы дат текущей половины года |
| `schedule` | четыре строки, по курсу: `course`, `semester`, `dates` (`"1"`–`"3"` и `"deadline"` — `ГГГГ-ММ-ДД` или `null`), `current_stage` — к какой опроцентовке сейчас проверяются работы курса (`null` — итоговая сдача или даты не заданы) |
| `groups` | группы студентов, преподавателей и исправленные: `group`, `course` (действующий или `null`), `course_by_number`, `course_overridden`, `manual` (добавлена администратором и пуста — держится в списке только его записью, её можно удалить), `semester`, `students`, `teachers` |

Ошибки ввода — `400`, `VALIDATION_ERROR` с `field`: `half`, `courses`, `1`–`3` и `deadline` (дата: формат, вне половины года, не по порядку), `group`, `course`, `name`. Нет пользователя — `404`, `NOT_FOUND`.

Студенту `GET /me` дополнительно отдаёт `deadline` — срок сдачи его курса (`ГГГГ-ММ-ДД` или `null`); экран загрузки показывает его рядом с этапом.

## 15. Поля для нового интерфейса и время — **сделано 25.10.2026** (решение 12)

**Время в ответах — по Минску**, без часового пояса: `2026-10-25T10:02:00`. Бэкенд при запуске ставит себе пояс `Europe/Minsk`, поэтому от пояса машины (VPN для ngrok) время не зависит; интерфейс показывает его как есть, без перевода в пояс телефона. Время с поясом (`…Z`, `…+03:00`) интерфейс тоже понимает и переводит в минское.

`GET /submissions` (студент) — новые поля:

| Поле | Тип | Что значит |
|---|---|---|
| `parent_id` | число или `null` | предыдущая версия этой работы (решение 9); по цепочке интерфейс собирает версии, а не по имени файла |
| `version` | число | номер версии, с 1 |
| `work_type` | строка или `null` | вид работы: дипломная в 8 семестре, иначе — с титульного листа (раздел 7); `null` — пока не распознан |
| `teacher_id`, `teacher_name` | число, строка | кому сдана работа — для «Загрузить новую версию» тому же преподавателю |
| `failure_code` | строка или `null` | причина сбоя проверки (`queue-v2.md`, раздел 5; `STUCK` — проверка зависла); интерфейс показывает её словами |

`GET /teacher/submissions` и `GET /teacher/history`: `student_name` — ФИО **без** «(гр. …)», группа — отдельным полем `student_group`; в истории добавлен `version`.

Тексты ошибок — короткими фразами для людей; ошибки проверки входа (`NO_INIT_DATA`, `INIT_DATA_FORMAT`, `INIT_DATA_SIGNATURE`, `INIT_DATA_EXPIRED`) — тоже по-русски: «Откройте приложение из Telegram.», «Сессия устарела. Закройте и откройте приложение.» Интерфейс по-прежнему показывает поле `error` как есть.

## 16. «Красная зона» администратора — **сделано 26.10.2026** (решение 13)

Состояние обработчика и модель, которая проверяет работы. Только для `role = ADMIN`, иначе `403`. Изменение действует для новых заданий сразу, без перезапуска, и возвращает экран целиком.

| Метод | Тело | Что делает |
|---|---|---|
| `GET /admin/system` | — | экран |
| `PUT /admin/system/model` | `{"model": "heavy", "confirm_cloud": false}` | модель проверки по id из списка обработчика; `model: null` или id модели по умолчанию — снова по умолчанию. Облачная — только с `confirm_cloud: true`, иначе `409`, `CLOUD_CONFIRMATION_REQUIRED`. Модель недоступна — `409`, `MODEL_UNAVAILABLE`; обработчик ещё не сообщил о себе — `409`, `WORKER_UNKNOWN`; нет такой — `400`, `UNKNOWN_MODEL` |

**Экран:**

| Поле | Что значит |
|---|---|
| `worker` | `known` — обработчик сообщал о себе; `online` — последнее сообщение не старше 150 с (обработчик пишет раз в минуту, во время долгой проверки — после неё); `last_seen`, `seconds_ago`; `mode`, `llm_mode`, `cloud_allowed`, `kb_version` — из его сообщения (`queue-v2.md`, раздел 10) |
| `models` | модели обработчика: `id`, `title`, `tier`, `model`, `cloud`, `available`, `reason`, `note` |
| `default_model` | модель по умолчанию у обработчика |
| `selected` | выбор администратора или `null` |
| `active` | чем будут проверяться новые работы: `selected` или модель по умолчанию |
| `changed_at`, `changed_by` | когда и кто выбрал (ФИО администратора); `null`, если выбора нет |

Выбор хранится в `academic_settings` (ключ `llm_model`, с `updated_by`) и пишется в журнал бэкенда с Telegram ID администратора. Адреса моделей и ключи бэкенд не знает: каталог — у обработчика (`worker-python/llm-models.yaml` и `.env`).

## 17. `GET /submissions/{id}/commented` — работа с комментариями автопроверки, **сделано 29.10.2026** (решение 14)
